# AI 阅读助手 · 划词即问

阅读网页文档时，选中任意文字即可调用**你自己的大模型**即时解释、翻译、举例、深入、追问；答案流式输出、自动存档，随时导出成 Markdown 笔记。

Chrome / Edge 通用（Manifest V3，零依赖，无需构建）。

## 功能

- **双击选词即问**：双击一个单词就直接开始回答，连气泡都不用点。三击选中整段时仍会先给气泡，让你自己挑动作。
- **分层回答**：第一屏只给「一句话结论 + 2~3 条要点」，细节、原理、例子收在「展开细节」后面，想看再点开。答案不会一上来就砸一脸。
- **划词气泡 + 右侧对话面板**：选中文字后旁边只浮出一排动作按钮（不遮挡正文），点「解释 / 翻译 / 举例 / 深入」后，**在右侧展开完整对话面板**——全高显示、消息按轮次累积、支持多轮追问与「重答」。
- **不挤占阅读**：面板宽度拖左侧边缘即可调整（会自动记住），需要腾出空间时点标题栏的「—」最小化为悬浮球，随时点回。
- **上下文感知**：自动带上选区所在的段落和页面标题，模型知道你在读什么。
- **自动存档**：每次问答按「页面 + 选区 + 模式」幂等去重后存入本地，可在设置页搜索、筛选、收藏、删除。复制与存档都会带上折叠的展开层，不会只给半截答案。
- **导出 Markdown**：按 域名 → 日期 → 条目 组织，导出后直接就是一篇可用的笔记。
- **快捷键**：`Alt+Shift+E` 解释当前选中内容；右键菜单支持解释 / 翻译 / 追问。
- **自带密钥**：OpenAI 兼容协议通吃 DeepSeek、Kimi、通义、智谱、硅基流动、Ollama、LM Studio；也支持 Anthropic 原生协议。

## 安装（开发者模式加载）

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 打开右上角 **开发者模式**
3. 点 **加载已解压的扩展程序**，选择本目录（`ai-reader`）
4. （可选）要在**本地 HTML 文件**上使用：扩展详情页 → 开启「允许访问文件网址」

## 配置模型

1. 点工具栏图标 → **设置**
2. 选一个服务商预设（或选「自定义」填任意 OpenAI 兼容地址）
3. 填入 API Key 和模型名
4. 点 **保存并测试连接**

「保存并测试」会真的发起一次极短的模型请求，同时验证接口地址、密钥、模型名三件事——测试通过就一定能用。首次保存时会弹窗申请**接口域名**的联网权限（只申请你填的那个域名，不申请全站）。

本机模型（Ollama / LM Studio）无需 Key，随便填一个占位值即可。

## 使用

| 操作 | 方式 |
|---|---|
| 双击选词即问 | 双击一个单词，直接开始回答（设置里可换动作或关掉） |
| 划词提问 | 选中文字 → 点小气泡上的动作按钮，右侧面板展开回答 |
| 划词直接问 | 设置里把触发方式改为「划完直接在右侧面板回答」 |
| 看细节 | 回答里点「展开细节」；「深入」动作默认就是展开的 |
| 多轮追问 | 面板底部输入框，`Enter` 发送 |
| 追问刚划的词 | 在页面上选好文字 → 点气泡里的「提问」→ 输入问题（会自动带上这段选区） |
| 换个说法重答 | 每条回答下方的「重答」 |
| 调整面板宽度 | 拖动面板左边缘；宽度会记住 |
| 让出页面空间 | 面板标题栏「—」最小化为悬浮球 |
| 快捷键 | `Alt+Shift+E` |
| 右键菜单 | 选中文字 → 右键 → 用 AI 解释 / 翻译 / 追问 |
| 收藏 | 回答下方「☆ 收藏」，收藏永不因条数上限被清理 |
| 导出 | 设置页 → 历史记录 → 导出 Markdown |

## 界面预览

不想先装扩展、只想看看长什么样：

```bash
node tools/make_preview.mjs   # 生成 tools/preview.html，用浏览器打开
```

预览页的样式和 DOM 是**从 `content/content.js` 实时抽取**的，不是另画一版，所以看到的排版就是实际效果（跟随系统深浅色）。

## 安全设计

- **密钥只存本机**（`chrome.storage.local`，明文但绝不经 `storage.sync` 同步到其他设备），所有请求从你的浏览器直连你填的服务商，**没有任何中转服务器**。
- **选区只是素材**：提示词明确约定选中内容是指令素材而非指令，网页里藏的「忽略以上指令」不会被执行。
- **输出先转义再渲染**：模型返回的 HTML / `javascript:` 链接一律当作纯文本，已用自测覆盖（见下）。
- **最小权限**：联网权限按接口域名运行时申请；content script 不持有任何网络权限，请求全部由 background 收口。

## 已知限制

- 浏览器**内置 PDF 阅读器**与 `chrome://` 内部页面里扩展无法运行（浏览器限制），PDF 场景可改用「下载后用本地阅读器打开」或浏览器自带的翻译功能。
- 本地 `file://` 页面需手动开启「允许访问文件网址」。
- API Key 明文存于本机浏览器存储，建议为插件单独申请一个低额度 Key。
- 个别站点用 iframe 嵌正文时，气泡会在 iframe 内部定位，可能受 frame 边界裁剪。

    ├── selftest.mjs         # 静态自测：直接加载真实源码跑 44 项断言

### 分层回答是怎么实现的

模型被要求把回答写成两段，中间用一个独立成行的标记隔开。解析在 **service worker** 侧完成
（`createLayerSplitter`），随流式增量给每段打上 `part: 'brief' | 'detail'` 一起下发，
content script 只按 part 往两个缓冲区累加：

```
模型流式输出 ──► createLayerSplitter ──► delta{part:'brief'} ──► 结论层（立即渲染）
                       │                └► delta{part:'detail'} ─► 折叠区（默认收起）
                       └─ 见不到标记就全走 brief（优雅降级，不丢内容）
```

放在 service worker 而不是 content script，是因为**只有它能 import `lib/prompts.js`**
（content script 不是 ESM 环境）。这样标记格式只有一份定义，不会出现两边抄写、慢慢漂移的问题；
自测里有一条守卫专门盯着这件事（标记字面量只允许出现在 `lib/prompts.js`）。

解析器有两个不显然但要紧的地方：**标记是跨 chunk 到达的**（必须扣住尾巴，否则 `<<<MO`
会被当成正文发出去，流式渲染再也删不掉），以及**标记前后的空行要吃掉**
（否则流式期间结论层多一个空段，等收尾时又缩回去，用户会看到一次跳动）。
自测用「逐字符推送的结果必须与一次性输入完全一致」把这两点钉住了。

### 三道测试，各管一段

```bash
node tools/selftest.mjs   # 快，不需要浏览器：逻辑、安全、结构一致性
node tools/e2e.mjs        # 慢，需要本机 Chrome：划词交互链路
node tools/e2e-ui.mjs     # 慢，需要本机 Chrome：扩展弹窗与设置页
npm run test:all          # 三道一起跑
```

**selftest.mjs** 覆盖：Markdown 渲染器 XSS 防护、各种 Base URL 的端点补全、提示词防注入与截断、
**分层标记的增量解析**、记录 id 稳定性、导出格式；以及结构一致性 —— 模板里的 class 是否都有样式、
每个 `data-act` 是否都有处理分支、气泡定位是否避让面板、事件守卫是否用对了 API、
popup/options 两页的 `hidden` 不变量是否被 CSS 盖掉、JS 引用的元素 id 是否真的存在、
复制与存档是否带上了折叠的展开层。

**e2e.mjs** 用 CDP 派发**真实的鼠标按下 / 移动 / 抬起**（不是 `el.click()` 那种合成事件），
走完「拖选正文 → 气泡浮出 → 点动作 → 右侧面板弹出 → 请求发往后台 → 重新划选」全链路，
并断言 `click` 最终落在哪个元素上；此外还覆盖**真实双击**（`clickCount` 递增，浏览器才会把
`detail` 置为 2）与**真实三击**，以及分层回答的折叠 / 展开 / 流式重绘后状态不丢。

**e2e-ui.mjs** 起一个本地静态服务（`file://` 下 Chrome 会拒绝加载 ES module，测不出真东西），
在文档创建前注入 `chrome.*` 桩，然后加载**真实的 popup.html / options.html**，
断言「未配置 / 已配置 / 后台不可达」三种状态各自的呈现，以及一条通用不变量：
**凡带 `hidden` 属性的元素，计算样式必须是 `display:none`**。

> 为什么三道都要：静态检查和合成事件都发现不了「在 `mousedown` 里把自己 `display:none` 掉，
> 于是按钮永远收不到 `click`」（v1.1.1），也发现不了「`[hidden]` 被 `.class{display}` 静默盖掉，
> 于是提示条永远显示」（v1.1.2）——前者要真实输入，后者要真实计算样式。
>
> 有头模式跑（便于肉眼观察）：`HEADED=1 node tools/e2e.mjs`；
> Chrome 不在默认位置时：`CHROME_PATH=/path/to/chrome node tools/e2e.mjs`。

## 更新记录

- **1.2.0** 两点交互改进：
  - **双击选词即问**：双击直接开始回答，不再需要把鼠标移到气泡上点一下。三击仍走常规流程
    （选中的是一整段，意图不同）。实现上靠 `mousedown` 的连击序号区分二击与三击，
    并在双次抬起后留 180ms 的沉降窗口，避免连击被误吞。
  - **分层回答**：结论层先行、展开层折叠，`深入` 动作默认展开。解析在 service worker 完成
    （见上文「分层回答是怎么实现的」），模型没输出标记时优雅降级为单层。
    折叠状态记在数据上而非 DOM 上，流式重绘不会把用户展开的内容折回去。
  - 设置页新增「双击选词直接提问」「双击时用的动作」「分层回答」三项，均为独立开关；
    记录结构新增可选的 `detail` 字段，旧记录无此字段即按单层处理，**无需数据迁移**。
  - 静态自测 32 → 44 项，端到端 15 → 33 项。
- **1.1.2** 修复：配好 API Key 后，弹窗仍提示「还没有配置模型」。成因是 `popup.css` 里的
  `.tip { display: flex }` 盖掉了 `hidden` 属性（`hidden` 只是 UA 样式表里的一条规则，优先级最低），
  提示条于是永远显示；靠 CSS 加 `[hidden] { display: none !important; }` 兜底解决。
  同时：配置缺失时明确列出缺哪一项、读不到设置时如实报错而不是假装未配置；
  设置页新增「有改动还没保存」提示（「仅测试」不写存储，是这类困惑的另一个常见成因），
  并在未保存就关页面时给出提醒。测试增至三道（新增扩展页面回归）。
- **1.1.1** 修复：点气泡上的动作按钮后，右侧面板不弹出。成因是 UI 归属判断误用了
  `Element.composedPath`（那是 `Event` 的方法，恒为 `undefined`），于是连点自家气泡也被当成
  「点了页面别处」，气泡在 `mousedown` 阶段就被隐藏，`click` 因此被派发给 `<html>`，
  按钮的处理器永远不执行。同一处修复也让「同一段文字重新划选」能再次浮出气泡。
  新增端到端回归测试与两条静态守卫。
- **1.1.0** 交互改版：气泡降级为纯触发器，答案迁到右侧可调宽对话面板。
- **1.0.0** 首个版本。
